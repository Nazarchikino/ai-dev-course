# room-booking — Сервіс бронювання аудиторій коледжу

REST API сервіс на базі Node.js та Express 5 для перегляду аудиторій, перевірки вільних часових проміжків, створення та скасування бронювань.

## 1. Призначення та цільова аудиторія

Сервіс `room-booking` призначений для автоматизації обліку зайнятості аудиторного фонду навчального закладу (аудиторій, комп'ютерних класів, актової зали) та запобігання накладкам у розкладі занять і позанавчальних заходів.

**Для кого призначений проєкт:**
- **Викладачі та куратори груп** — для оперативного пошуку вільного часу (`GET /api/rooms/:id/free`) та резервування аудиторій під консультації, додаткові заняття, заліки чи гуртки.
- **Працівники навчальної частини та диспетчери розкладу** — для контролю завантаженості аудиторій за датами та оперативного скасування бронювань (не пізніше ніж за 2 години до початку).
- **Розробники внутрішніх сервісів коледжу та здобувачі освіти** — як бекенд-ядро для інтеграції з веб-кабінетом або Telegram-ботом розкладу, а також як навчальний зразок побудови та документування REST API.

## 2. Бізнес-правила бронювання

Усі операції створення та скасування бронювань підпорядковуються таким правилам (реалізованим у `src/bookings.js` та `src/slots.js`):

1. **Формат дати і часу:** дата передається у форматі `"РРРР-ММ-ДД"` (наприклад, `"2026-11-02"`), час — у 24-годинному форматі `"ГГ:ХХ"` з провідним нулем (наприклад, `"08:30"`).
2. **Коректність інтервалу:** час закінчення `to` має бути суворо пізнішим за час початку `from` (`to > from`), інакше повертається помилка `400 Bad Request`.
3. **Години роботи аудиторії:** бронювання має повністю вкладатися у графік роботи обраної аудиторії (`opens <= from` та `to <= closes` згідно з `data/rooms.json`), інакше повертається `400 Bad Request`.
4. **Максимальна тривалість бронювання:** тривалість одного бронювання не може перевищувати `MAX_BOOKING_HOURS` годин (за замовчуванням — **4 години** або 240 хвилин), інакше повертається `400 Bad Request`.
5. **Напіввідкриті інтервали та відсутність перетинів:** часові проміжки трактуються як напіввідкриті інтервали `[start, end)`. Суміжні бронювання, що лише торкаються межами (наприклад, `10:00–11:20` та `11:20–12:40`), не конфліктують. У разі накладання з існуючим бронюванням повертається `409 Conflict`.
6. **Мінімальний строк скасування:** скасувати бронювання (`DELETE /api/bookings/:id`) можна не пізніше ніж за **2 години** (`MIN_CANCEL_HOURS = 2`, змінено з 24 годин у версії `1.2.0`) до моменту його початку, інакше повертається `409 Conflict`.

## 3. Вимоги та встановлення

- **Node.js** версії LTS (рекомендовано `>= 20.x`) та пакетний менеджер **npm**.

Клонування репозиторію та встановлення залежностей:

```bash
cd practice11
npm install
```

## 4. Налаштування середовища

Скопіюйте файл `.env.example` у `.env` (за потреби) або передайте змінні середовища перед запуском:

| Змінна середовища | Значення за замовчуванням | Опис |
| :--- | :---: | :--- |
| `PORT` | `3000` | HTTP-порт, на якому запускається Express-сервер (`src/server.js`) |
| `MAX_BOOKING_HOURS` | `4` | Максимальна дозволена тривалість одного бронювання в годинах (`src/bookings.js`) |

## 5. Команди запуску та перевірки

| Команда | Призначення |
| :--- | :--- |
| `npm start` | Запуск HTTP-сервера (`node src/server.js`) на `http://localhost:3000` |
| `npm test` | Запуск автоматизованих тестів Jest (`tests/slots.test.js`, `tests/api.test.js`) |
| `npm run docs:check` | Статична перевірка типів у JSDoc (`tsc -p jsconfig.json`) та лінтинг повноти JSDoc (`eslint src`) |
| `npm run docs:html` | Генерація HTML-довідника API у каталог `docs/api/` (`jsdoc -c jsdoc.json`) |
| `npx @redocly/cli lint docs/openapi.yaml` | Валідація специфікації OpenAPI 3.1 |

## 6. Довідник маршрутів HTTP API

| Метод і маршрут | Параметри запиту / тіло | Коди відповідей | Опис |
| :--- | :--- | :--- | :--- |
| `GET /api/rooms` | — | `200 OK` | Повертає список усіх аудиторій коледжу з `data/rooms.json` |
| `GET /api/rooms/:id/bookings` | Path: `id` (рядок)<br>Query: `date` (`"РРРР-ММ-ДД"`) | `200 OK`, `404 Not Found` | Повертає список бронювань аудиторії `id` на вказану дату |
| `GET /api/rooms/:id/free` | Path: `id` (рядок)<br>Query: `date` (`"РРРР-ММ-ДД"`), `min` (хвилини, за замовчуванням `45`) | `200 OK`, `404 Not Found` | Повертає вільні часові вікна аудиторії тривалістю не менше `min` хвилин |
| `POST /api/bookings` | Body JSON: `{ roomId, date, from, to, who }` | `201 Created`, `400 Bad Request`, `404 Not Found`, `409 Conflict` | Створює нове бронювання після перевірки всіх бізнес-правил |
| `DELETE /api/bookings/:id` | Path: `id` (число) | `204 No Content`, `404 Not Found`, `409 Conflict` | Скасовує бронювання за числовим `id` (якщо до початку >= 2 год) |

### Приклад створення бронювання

```http
POST /api/bookings HTTP/1.1
Content-Type: application/json

{
  "roomId": "204",
  "date": "2026-11-02",
  "from": "10:00",
  "to": "11:30",
  "who": "Тимченко С. В."
}
```

## 8. Відомі обмеження

1. **Зберігання стану в оперативній пам'яті (`in-memory`):** усі створені бронювання зберігаються в масиві `bookings` усередині замикання `createBookingService` (`src/bookings.js`). Після перезапуску процесу Node.js усі бронювання втрачаються, а масштабування у кілька процесів (кластеризація) неможливе без переходу на зовнішню СКБД (див. [ADR 0001](docs/adr/0001-in-memory-booking-storage.md)).
2. **Відсутність автентифікації та авторизації:** API є відкритим (`security: []`), поле `who` передається клієнтом як довільний текст, і будь-який користувач може скасувати чуже бронювання, знаючи його числовий `id`.
3. **Залежність від локального часового поясу сервера:** під час перевірки строку скасування в `cancel` момент початку бронювання конструюється через `new Date(\`${booking.date}T${booking.from}:00\`)` без зазначення часової зони, тому обчислення виконується у місцевому часовому поясі ОС сервера.
4. **Відсутність автоматичного підвантаження `.env`:** сервіс звертається до `process.env.PORT` та `process.env.MAX_BOOKING_HOURS` напряму без пакета `dotenv`, тому змінні середовища потрібно передавати через оболонку ОС або прапорець `node --env-file=.env src/server.js`.
5. **Обмежена валідація формату дати та вхідних параметрів:** формат часу `"ГГ:ХХ"` суворо перевіряється регулярним виразом у `toMinutes` (викидаючи `RangeError`, який без `status` повертається клієнту як `500`), проте формат дати `"РРРР-ММ-ДД"` у `list` і `create` не валідується регулярним виразом.
