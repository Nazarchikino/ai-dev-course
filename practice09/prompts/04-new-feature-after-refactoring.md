# Завдання 9. Реалізація нової вимоги після рефакторингу (`feat:`)

## Запит до AI-асистента
```text
Реалізуй нову вимогу у [# src/report.js]:
студента без оцінок (grades.length === 0) показувати як «н/а» (без позначки [!]) і не враховувати в середньому балі групи та списку «Потребують уваги».
Дотримуйся обмежень ESLint (complexity <= 4, max-depth <= 2, max-lines-per-function <= 30, no-var).
Онови тест «дивність» для студента без оцінок у [# tests/report.characterization.test.js] на тест нової вимоги.
```

## Чому оновлення знімків (`npx jest -u`) у Завданні 9 є правильним
- Під час **рефакторингу** (Завдання 3–8) зовнішня поведінка системи за означенням не повинна змінюватися, тому падіння snapshot-тесту сигналізує про помилку рефакторингу, і оновлювати знімки (`jest -u`) категорично заборонено.
- У **Завданні 9** виконується **доопрацювання (нова функціональна вимога, коміт `feat:`)**, яке цілеспрямовано змінює зовнішню поведінку для студентів із порожнім масивом оцінок `grades: []` (зокрема для студентки `"Кравець Софія"` у фікстурі `tests/fixtures/group.json`).
- Оскільки специфікація змінилася свідомо і точковий модульний тест нової вимоги підтвердив правильність нового формату (`Кравець Софія — н/а`, середній бал групи `3.4 (задовільно)`, `Потребують уваги: Мельник Іван`), оновлення еталонного знімка командою `npx jest -u` фіксує нову затверджену поведінку системи.
