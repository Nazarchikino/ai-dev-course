# Завдання 1–2. Огляд коду, метрики «до» та характеризаційні тести

## Запит на створення характеризаційних тестів (Завдання 2)
```text
Склади характеризаційні тести на Jest для функції buildReport з [# src/report.js].
Мета – зафіксувати ПОТОЧНУ поведінку, а не перевірити правильність.
Використай toMatchSnapshot для повного тексту відомості на [# tests/fixtures/group.json]
у звичайному та скороченому режимі (opts.short).
Окремо перевір: порожню групу; студента без оцінок; межові значення шкали 4.5, 3.5, 2.5;
значення opts: undefined, null, {}.
Не змінюй src/report.js.
```

## Виявлені дивності поточного коду (не виправляються під час рефакторингу)
1. **Студент без оцінок (`grades: []`):** отримує середній бал `0`, через що йому присвоюється рівень `"незадовільно"`, додається тривожна позначка `[!]`, його ім'я додається в рядок `"Потребують уваги"`, а `0` враховується у дільнику `cnt2` середнього бала групи (занижуючи середній бал групи `456-Д` з `3.4` до `2.7`).
2. **Порівняння з порогом до округлення `toFixed(1)`:** рівень (`"відмінно"`, `"добре"` тощо) обчислюється за невідкругленим числом `d`, а виводиться `d.toFixed(1)`, тому середній бал `4.4545...` виводиться як `"4.5 (добре)"`.
3. **Скорочення імені (`opts.short`):** конструкція `s.name.split(" ")[0] + " " + s.name.split(" ")[1][0] + "."` двічі розбиває рядок і жорстко припускає наявність другого слова (для імені з одного слова виникає `TypeError`).
