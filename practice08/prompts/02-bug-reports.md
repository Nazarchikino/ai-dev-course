## Звіт #1: Дата видачі в записі збігається з датою повернення

### Варіант А — Короткий запит (`/fix` / «виправ помилку»)
```text
Виправ помилку у функції dueDate в [# src/library.js].
```
**Відповідь на короткий запит:**
```js
function dueDate(issueDate, days = LOAN_DAYS) {
  const result = new Date(issueDate);
  result.setDate(result.getDate() + days);
  return result;
}
```
*Аналіз:* Асистент запропонував робочий код клонування дати, але без посилання на функцію `issueBook` та без пояснення, чому в записі про видачу змінювалося поле `issuedAt`.

### Варіант Б — Повний звіт за шаблоном
```text
Функція dueDate (та issueBook) у [# src/library.js] працює неправильно.
Правило: п. 2 README.md — «Строк повернення — 14 днів від дати видачі. Дата видачі в записі про видачу після цього не змінюється».
Вхідні дані: issueDate = new Date(2026, 8, 10) (10.09.2026).
Очікувано: loan.issuedAt дорівнює 10.09.2026, loan.due дорівнює 24.09.2026.
Фактично: обидва поля loan.issuedAt та loan.due дорівнюють 24.09.2026.
Повний текст помилки (якщо є): логічна помилка без винятку (assertion failure у тесті).
Уже перевірив: у функції issueBook об'єкт issueDate передається у поле issuedAt і водночас у виклик dueDate(issueDate).
Знайди ПРИЧИНУ. Спершу поясни її, потім запропонуй мінімальне виправлення.
Не змінюй інші функції.
```
**Відповідь на повний звіт:**
- **Причина (одним реченням):** Метод `issueDate.setDate(...)` у функції `dueDate` змінює (мутує) переданий об'єкт `Date` за посиланням, тому в `issueBook` поля `issuedAt` і `due` вказують на один і той самий мутований екземпляр `Date`.
- **Мінімальне виправлення:** створити копію дати `const due = new Date(issueDate.getTime())` перед викликом `setDate`.

## Звіт #2: Немає штрафу за прострочення на межі місяців

### Варіант А — Короткий запит (`/fix` / «виправ помилку»)
```text
Виправ помилку у функції calculateFine в [# src/library.js].
```
**Відповідь на короткий запит:**
```js
function calculateFine(due, returnedAt) {
  const late = Math.floor((returnedAt - due) / (1000 * 60 * 60 * 24));
  if (late <= 0) return 0;
  return Math.min(late * FINE_PER_DAY, MAX_FINE);
}
```
*Аналіз:* Асистент замінив `getDate()` на ділення різниці в мілісекундах на `86_400_000` з `Math.floor`. Проте при переході на зимовий час (25.10.2026 в часовому поясі `Europe/Kyiv`) доба триває 25 годин, тому різниця між `new Date(2026, 9, 24)` та `new Date(2026, 9, 26)` становить `49` годин (`1.9583` доби), і `Math.floor` дасть `1` день (5 грн) замість `2` днів (10 грн)!

### Варіант Б — Повний звіт за шаблоном
```text
Функція calculateFine у [# src/library.js] працює неправильно.
Правило: п. 3 README.md — «Штраф — 5 грн за кожен день прострочення, але не більше 100 грн. Повернення в день строку або раніше — без штрафу».
Вхідні дані: due = new Date(2026, 8, 28) (28.09.2026), returnedAt = new Date(2026, 9, 3) (03.10.2026); а також перехід на зимовий час due = new Date(2026, 9, 24), returnedAt = new Date(2026, 9, 26) у TZ=Europe/Kyiv.
Очікувано: 25 грн (за 5 днів прострочення з 28.09 по 03.10) та 10 грн (за 2 дні з 24.10 по 26.10).
Фактично: 0 грн на межі місяців (оскільки 3 - 28 = -25 <= 0).
Повний текст помилки (якщо є): Expected: 25, Received: 0.
Уже перевірив: returnedAt.getDate() - due.getDate() враховує лише номер дня в межах місяця і не враховує місяць, рік та перехід на зимовий час.
Знайди ПРИЧИНУ. Спершу поясни її, потім запропонуй мінімальне виправлення.
Не змінюй інші функції.
```
**Відповідь на повний звіт:**
- **Причина (одним реченням):** Функція `calculateFine` обчислює різницю лише між номерами днів місяця (`getDate()`), ігноруючи місяць та рік, через що при переході в наступний місяць різниця стає від'ємною.
- **Мінімальне виправлення (стійке до DST):** нормалізувати обидві дати до календарних діб у UTC через `Date.UTC(d.getFullYear(), d.getMonth(), d.getDate())` і поділити різницю на `86_400_000` мс.

## Звіт #3: Не вдається видати книгу новому читачеві

### Варіант А — Короткий запит (`/fix` / «виправ помилку»)
```text
Виправ помилку TypeError: Cannot read properties of undefined (reading 'filter') у функції canBorrow в [# src/library.js].
```
**Відповідь на короткий запит (симптоматичний варіант з `try / catch` або `?.`):**
```js
function canBorrow(reader, loans) {
  try {
    const byReader = groupByReader(loans);
    const active = byReader[reader.id].filter((l) => !l.returnedAt);
    return reader.active && active.length < MAX_ACTIVE;
  } catch {
    return true;
  }
}
```
*(або варіант із `byReader[reader.id]?.filter(...)` без `?? []`, де `active?.length < MAX_ACTIVE` дає `undefined < 3 === false` і блокує видачу новому читачеві!)*

### Варіант Б — Повний звіт за шаблоном
```text
Функція canBorrow у [# src/library.js] працює неправильно.
Правило: п. 4 README.md — «Ліміт: читач може мати на руках не більше 3 книг одночасно. Новий читач, який ще не брав книг, може отримати книгу. Неактивному читачу видача заборонена».
Вхідні дані: reader = { id: 2, card: "ZV-0456/26", active: true }, loans = [] (або масив видач лише інших читачів).
Очікувано: canBorrow(reader, loans) повертає true.
Фактично: викидається виняток TypeError: Cannot read properties of undefined (reading 'filter').
Повний текст помилки (якщо є):
TypeError: Cannot read properties of undefined (reading 'filter')
    at canBorrow (src/library.js:37:38)
    at Object.issueBook (src/library.js:45:8)
Уже перевірив: groupByReader(loans) створює ключі лише для тих readerId, які присутні в масиві loans.
Знайди ПРИЧИНУ. Спершу поясни її, потім запропонуй мінімальне виправлення.
Не змінюй інші функції.
```
**Відповідь на повний звіт:**
- **Причина (одним реченням):** Для нового читача, який ще не має жодного запису в `loans`, у словнику `byReader` відсутній ключ `reader.id`, тому `byReader[reader.id]` повертає `undefined`, на якому викликається `.filter(...)`.
- **Мінімальне виправлення:** підставити порожній масив за замовчуванням для читача без історії видач: `const readerLoans = byReader[reader.id] || [];` перед викликом `.filter((l) => !l.returnedAt)` та явно приводити `Boolean(reader.active)`.
