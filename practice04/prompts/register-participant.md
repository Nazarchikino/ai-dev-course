# Запит із п’яти блоків для створення функції `registerParticipant` (Завдання 3)

**[Роль]**
Ти — досвідчений розробник на JavaScript (Node.js 20+, модульна система CommonJS `require` / `module.exports`), який пише чистий, надійний код із суворим дотриманням бізнес-вимог та контрактів даних.

**[Контекст]**
Ми розробляємо модуль реєстрації здобувачів освіти на події коледжу (олімпіади, хакатони, семінари).
- Наявне сховище даних у пам'яті та JSDoc-типи (`CollegeEvent`, `Participant`, `EventRegistry`) описані у файлі `#src/store.js`.
- Початкова постановка задачі наведена у `#docs/TASK.md`, а узгоджені бізнес-правила та відповіді замовника (пункти 1–9, 13–14) — у файлі `#docs/customer-answers.md`.

**[Завдання]**
Створи функцію `registerParticipant(registry, participant, now = new Date())` у файлі `src/registration.js` для реєстрації учасника на подію коледжу згідно з такими правилами:
1. **Перевірка часу закриття реєстрації**: порівняй `now` із `new Date(registry.event.registrationClosesAt)`. Якщо поточний момент `now` пізніший або дорівнює моменту закриття (момент закриття вже вважається закритим), викинь помилку `Error` із дослівним повідомленням: `"Реєстрацію закрито"`.
2. **Валідація та нормалізація даних учасника**:
   - Поля `email` і `fullName` є обов’язковими, поле `group` — необов’язкове.
   - Прибери пробіли по краях `email` і переведи його у нижній регістр (`.trim().toLowerCase()`). Якщо `email` не є непорожнім рядком, не містить символу `@` (з непорожньою частиною до `@`) або після `@` немає крапки в домені, викинь помилку типу `TypeError` із дослівним повідомленням: `"Некоректна електронна пошта"`.
   - Прибери пробіли по краях `fullName` (`.trim()`). Якщо після обрізання пробілів `fullName` порожній, викинь помилку типу `TypeError` із дослівним повідомленням: `"Вкажіть ПІБ"`.
3. **Перевірка дублікатів**: перевір, чи немає вже учасника з таким самим нормалізованим `email` як в основному списку `registry.registered`, так і в черзі `registry.waitlist`. Якщо є — викинь помилку `Error` із дослівним повідомленням: `"Учасник уже зареєстрований"`.
4. **Додавання до списку або листа очікування**:
   - Якщо в основному списку є вільні місця (`registry.registered.length < registry.event.capacity`), додай нормалізований об'єкт учасника у `registry.registered` і поверни `{ status: "registered" }`.
   - Якщо вільних місць немає, додай нормалізований об'єкт учасника у `registry.waitlist` і поверни `{ status: "waitlisted", position: registry.waitlist.length }` (де `position` — номер у черзі, починаючи з 1).

**[Обмеження]**
- Тексти всіх повідомлень про помилки (`"Реєстрацію закрито"`, `"Некоректна електронна пошта"`, `"Вкажіть ПІБ"`, `"Учасник уже зареєстрований"`) візьми дослівно, без жодних змін.
- Не змінюй файл `#src/store.js`.
- Не використовуй сторонніх бібліотек, баз даних чи надсилання листів-підтверджень.
- На цьому етапі реалізуй лише `registerParticipant` (без функції скасування реєстрації) і не додавай зайвих методів або полів.

**[Формат]**
Надай лише повний вміст файлу `src/registration.js` з JSDoc-коментарем українською мовою та експортом `module.exports = { registerParticipant };`, а після блоку коду — короткий перелік граничних випадків, які обробляє ця функція.
